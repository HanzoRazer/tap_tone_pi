## Summary

Created a thin coordinate-transform wrapper around the existing
`RayleighRitzResult.get_mode_shape()` method. Translates Phase 2 grid coordinates
(mm, configurable origin) into solver plate coordinates (m, corner origin),
evaluates the mode shape at each point, and returns predicted amplitudes keyed by
point_id.

This is the foundational module that bridges the Rayleigh-Ritz prediction engine
and the Phase 2 measurement workflow. DO-002 will consume the output to compute
prediction-vs-measurement residuals.

## Refinements from original DO-001 spec

A few things came out of implementation that weren't in the original spec:

**1. Axis mapping parameter.** The original spec didn't address which physical
direction the grid's +x and +y represent. Added `x_axis` and `y_axis` parameters
with values `"grain"` or `"cross_grain"`. Default is `x_axis="grain"`,
`y_axis="cross_grain"` (matches typical lutherie convention where x is along the
strings, which is along the grain on a soundboard).

**2. Origin dispatch table.** The original spec listed origin conventions
implicitly. Made it explicit via `ORIGIN_OFFSETS` dict with four entries
(lower_bout_center, plate_corner, soundhole_center, bridge_position). Adding new
conventions = adding entries. Two of the four (soundhole_center, bridge_position)
have placeholder offsets (25% and 70% of plate length); these may need
calibration against real designs.

**3. GridLike protocol instead of hard import.** Used Protocol-style
duck-typing dataclasses (`GridLike`, `GridPointLike`) instead of importing from
`scripts/phase2/grid.py`. Reasoning: `scripts/` isn't part of the package
(it's at the project root), and importing from it would create a fragile
dependency. Production code can pass any object with the same attributes.

**4. Normalization defaults to True.** The original spec didn't address
normalization. Added `normalize=True` default so amplitudes are scaled to peak
|amp| = 1.0. This is what DO-002's comparison code will want. `normalize=False`
returns raw solver values for debugging.

**5. Out-of-plate handling with epsilon tolerance.** Allowed 0.5mm overshoot
from plate edges before flagging as out-of-plate. Reasoning: floating-point
errors and CAD coordinate rounding shouldn't cause edge points to be rejected.

## Notes for downstream dev orders

**For DO-002 (comparison):** The output `RenderedModeShape.amplitudes_by_id` is
already normalized to peak=1.0 by default. When comparing against measured
amplitudes from `PointSpectrum.H_mag`, the measured values should also be
normalized to their peak before computing residuals, so both are on the same
scale.

**For DO-005/006 (analyzer GUI):** The visualization should preserve sign
information. Use a divergent colormap (RdBu_r) to show positive and negative
regions of the mode shape. The `RenderedModeShape` object is JSON-serializable
through standard dataclass conversion if needed for save/load.

**Potential follow-up work:**
- Adjust `soundhole_center` and `bridge_position` defaults once real Carlos
  Jumbo coordinates are available
- Add scattered-point evaluation optimization (currently each point is
  evaluated as a 1×1 mesh; could batch-evaluate for large grids)
- Consider exposing the swapped-axis transform as a named convention rather
  than parameter (e.g., `grid_axis_convention="grain_first"` vs `"cross_grain_first"`)

These are all incremental improvements, not blockers.
